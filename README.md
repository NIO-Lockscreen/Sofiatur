# Sofias biltur — Byåsen

Private static browser game. Touch-first Norwegian UI, on-rails driving with real branching roads and stops at junctions. Main trip: Herlofsons veg 3A → parking access by Skjermvegen barnehage, about 3.1 km.

## Run

`npm install` then `npm run dev`. The published static entry point is `dist/index.html`. Dependencies used at runtime are bundled locally; there are no map or elevation requests from the player's browser. Vite is used only for development.

## Data and representation

- Road centre lines, building footprints, mapped business/school/kindergarten names: OpenStreetMap API extract, 24 September 2026, ODbL. Source bbox: `10.325,63.393,10.369,63.406`. Attribution is present in the UI. Derived data is in `dist/map.json`.
- Address coordinate: Kartverket address API, Herlofsons veg 3A.
- Terrain: Kartverket elevation API DTM1. 2,560 measured points in a 40 m grid. The same bilinear interpolation drives roads, terrain and vehicle altitude. The rendered terrain mesh samples that surface at 8 m intervals. Height precision is therefore limited by the 40 m source sampling, especially banks and driveways.
- Mapped buildings are extruded on their actual footprints. Storey counts are read if available; missing heights, colours, roofs and windows are stylized. Vegetation is procedural. These are not photogrammetric/faithful facade reconstructions.
- Google Maps driving directions were inspected to validate the primary route; Street View at the starting street was inspected for visual reference. No Google imagery is copied into the game.
- The game uses the physical kindergarten at Skjermvegen 78B. Municipal organizational contact information lists Adolf Andreassens veg 6, which is not used as the destination.
- Private driveways are scenery rather than route choices, except home/destination access. One-way streets are directed; destination-only roads have a route penalty. Map-boundary branches without a legal route back to the goal are not offered.

## Renderer

Three.js 0.170.0, MIT license in `dist/vendor/THREE-LICENSE.txt`. iPad uses WebGL2 with capped resolution, batched geometry, distance culling, and local shadows. If WebGL is disabled, a lower-resolution software 3D rasterizer provides a fallback. The cloud QA browser lacks WebGL; hardware rendering and physical iPad performance remain unverified.

## Validation

`node verify-game.mjs` runs the actual game state machine with a mocked renderer and DOM. It covers start, invalid choices, complete 3 km route, victory, replay, and an alternate route. Browser UI start/choice controls were checked with the software renderer. WebMCP is feature-detected; the cloud browser does not expose modelContext, so browser registration validation is unavailable.

## Rebuilding geographic data

Run `python fetch-osm.py` (it downloads both documented OSM boxes and merges them into `byasen.osm`), then `python prepare-map.py` and `python fetch-terrain.py`. The terrain script uses the public Kartverket API with up to 50 points per request, 6 concurrent requests, and caches responses. Source downloads and transient cache files are ignored by Git. No API keys are needed.

## Roundabout controls
At each roundabout entry the game offers every exit that is not a blindvei once, numbered in travel order; if only one exit leads on, the car drives through the circle by itself. Direction arrows use the outgoing road relative to the approach, and no exit is visually recommended. Selecting an exit creates one continuous path through the directed OSM roundabout; speed is capped at 25 km/h inside the circle. “Angre rundkjøring” restores the last entrance, distance counter and choices, during or after the turn. Restart and arrival clear the undo point.

Run `node verify-roundabouts.mjs` for every mapped entrance and exit, including touch selection, automatic traversal and undo.

Free driving is available in settings: automatic acceleration up to 90 km/h, A/D or arrows to steer, Space to drift, Down/S to brake. Q and the recovery button snap to the nearest road with the tangent closest to the previous body heading, independently of OSM node order. The guided trip accelerates to 200 km/h between decisions.

## Blindveier · 28 September 2026
By default dead ends are no longer offered as choices; “Blindveier” in settings turns them back on. (Since 29 September 2026 the setting is on by default; see the last section.) A road counts as a blindvei when neither the kindergarten nor home can be reached from it without turning around or driving back through the same junction; this includes no-through residential loops and roads that end at the map edge. Home and the kindergarten entrance stay selectable. When only one road is left, for example a right turn where straight ahead is a blindvei, the car drives on by itself and keeps its speed until the next real choice, braking only within 55 m of it; an automatic roundabout is entered at circle speed. The main trip has 17 choices instead of 26. With blindveier on, every road is offered and the car slows at each junction as before.

Run `node verify-dead-ends.mjs` to explore every junction reachable from home and check that no offered road is a dead end, that speed is kept through automatic junctions, and that the setting restores the dead ends.

## Road height, choosing ahead and music · 28 September 2026
The car now rides on the drawn road. Roads are drawn as 8 m pieces laid on the terrain (`dist/road-surface.js`), while the car used to interpolate its height only between map nodes, up to hundreds of metres apart, and sank as much as 3 m below the road over crests. The guided trip now samples the road every 2 m on that same surface, and free driving uses it too. Where two drawn pieces meet at different heights on steep side slopes, the car rolls over the step rather than through it. Centre-line dashes follow the drawn road as well. Run `node verify-road-height.mjs` to drive every road against the drawn surface.

Arrows for the next open junction appear while the car drives, once that junction is within 250 m. Tapping one (or using the arrow keys) queues that road, up to two junctions ahead. The picked arrow lights up yellow for 0.8 s before any new arrows appear, and further taps are ignored meanwhile. The hint and the floating cue over the car show the plan. The car does not slow down for a queued junction; it enters a roundabout at circle speed. Run `node verify-queued-choices.mjs` for the whole trip on queued choices.

Soothing background music is generated with Web Audio in `dist/music.js` (pad chords, a soft bass and a music-box melody in F major), with no audio files. It starts with the drive, dips while the voice speaks and stops when the page is hidden. The ♫ button turns all sound (voice and music) on or off, and “Musikk” in settings turns only the music off.

## Saved settings and performance · 28 September 2026
“Musikk” and “Blindveier” are remembered in the browser (`localStorage`, key `sofiatur.innstillinger`). If storage is blocked, for example in private browsing, the game starts with the defaults. Run `node verify-settings.mjs`.

Performance, measured in headless Chromium (SwiftShader) at iPad size; absolute numbers on a real iPad differ:
- Loading takes 1.9 s instead of 5.5–6 s. Chunks are built straight into growing `Float32Array`s instead of plain arrays, and bus shelters, tram tracks and junction buildings look up nearby roads through a grid (`segmentIndex` in `transit-geometry.js`) instead of checking all 4,600 road segments. The generated geometry is unchanged.
- JavaScript memory after loading is 21 MB instead of 258 MB (peak 31 MB instead of 266 MB); the old build kept all temporary geometry arrays alive.
- Windows are drawn only on the outside of each wall. The copy facing into the building could never be seen. The scene has 1.16 million triangles instead of 1.41 million.
- The pixel ratio adapts: when many frames take more than 22 ms it steps down (to at least 0.8), and with steady headroom it steps back up to at most 1.6.
- Road curves are built once per road and reused, the minimap's roads and areas are painted once, static chunks skip per-frame matrix updates, and the camera no longer allocates objects every frame. The game's own JavaScript per frame dropped from 0.18 ms to 0.02 ms on average over the whole trip.

## Street details · 29 September 2026
**Why.** A junction was only grey road strips meeting, although the OSM extract has what makes a Norwegian street recognisable. `add-street-details.py` reads it from `byasen.osm` and adds one key, `street`, to `dist/map.json`. `dist/street-details.js` draws it. Only what lies in the map region and beside a drawn road is kept. Sources, tags and what is approximate: `docs/street-details.md`.

**On the road.** 63 zebra crossings are white stripes (0.5 m with 0.5 m gaps) across the carriageway, with a blue gangfelt sign on each side; two crossings at signals have two lines instead. Every entrance to the eight roundabouts and 11 mapped give-way points have a row of white haitenner across the lane, and a vikeplikt sign; the roundabout arms are not in OSM but a Norwegian roundabout is always entered giving way. The Palermo signals have stop lines. 23 speed tables and 7 humps are gentle raised bands with white triangles on the ramps (the car does not bump; a crossing on a table has its stripes on it). The 15 turning circles at the end of cul-de-sacs are round asphalt areas, radius 8.5 m or less where a house is close, level with the road end. Traffic islands are raised 12 cm with a light kerb and grass or paving; where OSM's island lies over the road centre line the car follows (the arms at Byåsveien / Arnt Smistads veg), it is drawn as a flush hatched island instead, and every island is cut through where a zebra crossing runs over it. Each roundabout also gets a kerbed grass island in the middle.

**Beside the road.** 99 sidewalks (light paving, 2.2 m; 44 of them untagged footways beside a road) and 123 gang- og sykkelvei (asphalt, 3 m), 27 km in all, lie on the ground with a small lift. They are pushed out to at least 0.4 m from the road's kerb band and cut where they run over a carriageway. 118 street lamps (where OSM has them) are slim grey poles, 7.6 m, with an arm over the road and a lamp head.

**Rebuild order:** `fetch-osm.py`, `prepare-map.py`, `add-lakes.py`, `add-dalgard.py`, `add-stavset.py`, then `add-street-details.py` (idempotent: it replaces `street`). `world.js` has one call after `addStavsetDetails` that draws it and keeps trees off the paths and the roundabout islands (`indexStreetDetails`); everything on a road stands on `roadTop`, everything beside it on `height`.

**Performance,** same headless Chromium: 1,689,112 -> 1,703,435 triangles (+0.85 %; the module draws 20,600, about 1.2 %), and building the world takes 3.4-3.8 s before and after. Drawing the details takes 0.12-0.16 s of that. The trees are planted by a seeded loop that draws random numbers only for trees that pass `clear()`, so keeping them off the paths shifts every tree after them: the forest is as dense as before but grows differently.

Tests: `node verify-street-details.mjs` checks the count of each feature, that every zebra stripe lies on a drawn road, on the asphalt and 1 m from the next, that islands and turning circles are where OSM puts them (turning circles at road ends, raised islands 1.2 m from any centre line), that lamps and paths stay clear of the carriageway (0.2 m beyond the kerb band), that no tree can grow in a path (the same rule as `clear()`), and the triangle and time budget.

## Junction audit · 29 September 2026
Every junction of the main trip and of the detour to Stavset was compared with the Esri aerial photo (for viewing only, not in the repository) and with Statens vegvesen's road database (NVDB). The result, junction by junction, is in `docs/junction-audit.md`. The street network itself agreed with reality: every public street is a road of the game, none is missing or invented, the one-way pairs (KIWI, Dalgårdvegen, the roundabouts) are right. What differed was the shape and the size of things, and that is now data:

- **Carriageway widths.** Roads had a width by class only (6.5 m, residential 5.2 m, service 3.5 m). 191 ways now carry a measured `width` in `map.json`, from `road_widths.py` (applied by `map_fixes.apply_road_widths` in `prepare-map.py`), and `roadWidth()` in `dist/transit-geometry.js` uses it when it is there, the class defaults otherwise. Herlofsons veg is 4.0 m and Per Sivles veg 3.5 (gravel), Uglavegen 6.0, Arnt Smistads veg 6.0, Selsbakkvegen 7.0, Byåsveien 7.9-9.0, and the carriageways beside a splitter island 4.0-4.5 m (one lane), which makes the islands at the KIWI, Stavset, Lysverkvegen and Kystadlia roundabouts and at the Dalgårdvegen junction show instead of disappearing under two 6.5 m roads. The aerial photo cannot give a carriageway width (it shows sidewalk and verge as well, without kerb contrast), so the values are NVDB's "Vegbredde" (estimated by the road owner for municipal roads, computed from the road area for Byåsveien) and are attributed in `map.json` (`source.roadWidth`); the aerial was used to check them.
- **Roundabout islands.** The OSM rings lie 1-2.5 m outside the middle of the carriageway, so the islands were drawn 4-7 m too wide (Kystadlia and Lysverkvegen 15 m instead of 10 m, the KIWI roundabout 16 m instead of 12 m). `map_fixes.ROUNDABOUT_ISLANDS` holds the diameter of the grass island measured on the aerial for eight rings, and `fit_roundabouts` (called at the start of `prepare-map.py`) pulls the ring nodes in so the drawn island is that size. Exit order, arrows and choices are unchanged.

Not touched, for the road-surface and street-detail work: saw-tooth outer edges and flat arm ends on the roundabouts, missing splitter islands and mountable aprons, zebra crossings (all four arms of the big roundabout, Palermo, 35336635, 1974499038). Vognhallvegen looks connected to Arnt Smistads veg on the aerial, but the link is a cycleway in OSM and `Gang- og sykkelveg` in NVDB, so the game rightly leaves it a dead end.

## Road geometry · 29 September 2026
Roads used to be straight 8 m strips laid on the terrain, each corner at terrain height. They banked with the hillside, kinked at every grid cell border, left wedge gaps at bends and crossed each other at junctions. Now `dist/road-geometry.js` computes one plan and one profile for every road, and both the drawn road (`dist/road-surface.js`) and the car (`world.roadLine`, used by `roadPoints` in `game.js`) follow it, so the car stays on the drawn road.

**Plan.** Every free OSM vertex becomes a circular arc (`fillet(prev,vertex,next,type)`, a pure function: secondary/tertiary 30/20 m, residential/unclassified 12 m, service 6 m; the tangent length is at most 45 % of the shorter segment, so arcs never touch; a bend that would push the road further into a house than the sharp corner does gets a tighter radius). Fixed points never move: every edge end (junctions, road ends, parking places) and every roundabout ring vertex. Rings are closed Catmull-Rom curves through their vertices. Roads are dense centre lines with samples at most 2 m apart, 1 m on tight bends.

**Profile.** Along each road (roads that carry straight on through a node are one chain) the level is a smoothing spline of the terrain under the centre line, lifted a little where the ground rises on the uphill side, with a grade limit of 26 % (public roads) to 32 % (service) on the 1.45 times exaggerated terrain, since the terrain itself reaches 66 % on the roads. All roads at a junction share one level at the node; a side road starts along the through road's plane. A bridge deck is a straight ramp between its ends.

**Surface.** Continuous ribbons with mitre joins (carriageway level across, kerb band 0.7 m each side, lying 9 cm lower and wider underneath). At every node with two or more arms that do not simply carry on there is a junction patch: each arm is a strip, neighbours are joined by a curb return (radius 8 m secondary/tertiary, 5 m residential, 3 m service, less where the arms are short), straight edges where roads carry on, a mitre on the outside of a bend. Ribbons start at the patch mouth (setback) and 3 cm inside it. Patch heights follow the plane through the node and the arms' mouth levels. Kerb bands follow the patch outline, so a road's kerb never runs over another carriageway. Roundabouts get a grass island at the level of the inner kerb. Centre-line dashes follow the smoothed roads. Where two neighbouring arms leave at levels the short curb return between them cannot reach (a step face steeper than 45 degrees), the corner takes the mean of the two levels and each ribbon tilts into it over its first 4 m instead; the strip under each arm's fan lies 45 cm under the fan at the node, so it cannot show through where the fans dip.

**Ground.** `createRoadSurface(roads,height,data)` lowers the 8 m ground grid where it would poke through the road (each sample on the carriageway must have the ground 16 cm below, one pass of least-squares pulls on the three grid vertices) and draws verge strips from the kerb edge down to the ground where the road stands above it (batter 0.6). `world.height` is terrain plus that lowering, `heightAt` is still the highest drawn road at (x,z) or null. Each ground grid vertex is now looked up once and `bucket` uses numeric keys, which pays for most of the road work in build time. Within 24 m of a junction node the ground beside an arm (up to 5 m beyond its kerb, between it and its neighbour arm when they are 8 to 100 degrees apart) is kept just below that arm's road, so a hillside does not close over the wedge between two roads. Verge strips stop short of any other road (and of the wedge between two arms where they would cross it), and are left out along a bridge; the ground under a bridge deck is never lowered, so the valley stays. `surface.groundTop(x,z)` is the ground as it is seen (the ground mesh, or the verge strip over it), and `street-details.js` puts sidewalks, gang- og sykkelvei, signs and lamps on it (markings stay on `roadTop`). Junction patches have no setback on a bridge arm: they stop at the abutment. `heightAt(x,z,near)` takes an optional level and then prefers the surface at that level, so a road under a deck keeps its own height.

## Driving line: right-hand lane, arcs through junctions, speed from curvature · 29 September 2026
**Why.** The car followed each edge's centre line and switched to the next edge at the junction node, so at every turn it pivoted on the spot (main trip: 105 frames under 5 m radius, 69 under 2 m, e.g. 105 degrees in one frame at (713,-50); lateral acceleration up to 209 m/s2, since the speed only knew the roundabout cap and the braking for the next stop) and drove on the centre line.

**Lane.** `dist/driving-line.js` (pure geometry, no three.js) builds the car's line from `world.roadLine`. On a two-way road the car drives a quarter of the carriageway width (`roadWidth`) to the right of the centre line, on one-way roads, roundabout rings and single-lane service roads (under 4.6 m) it stays in the middle; at home, the gate and the parking places the lane eases to the centre over 9 m so the car stops on the node. A lane is smoothed (Gaussian, 2.2 m) and along the middle of a road its bends open out by up to 0.8 m (less on narrow roads: 0.5 m stays to the kerb), but not within reach of a junction connector.

**Junctions.** At every node the car leaves the lane it came along some metres before the node and joins the next lane some metres after it, on a cubic Bezier chosen by search: the shortest setback (2 to 22 m, unequal ends allowed) that gives the radius the turn deserves (`T0 / tan(phi/2)` with T0 = 5 m + half the wider road, 5.5 to 35 m; sharp turns over 110 degrees 4 m) without leaving the drawn road (checked with `world.surfaceTop`, every 5 cm on the best few). The car waits at one stop line per arm (`stopX`), the earliest connector start of the roads that can follow, at least 2.5 m before the node; a queued or automatic junction is driven through on the same arc. U-turns on a reversal are three-point (or, from a stand, two-point) turns: arcs of 3.6 to 5 m radius with cusps where the car reverses (`line.reversing`, the wheels turn the other way, the body direction stays continuous). Parking places, home and the gate still end at their node.

**Speed.** The limit along a line is sqrt(2.5 m/s2 / curvature) (curvature over a 3 m chord), plus the roundabout's 45 km/h; `planAhead` works it backwards through every line the car will drive without asking (queued roads, automatic junctions, roundabout plans) with braking at 4.5 m/s2 to where the car must slow (a stop, a crawl of 2.4 m/s at automatic junctions with blindveier on, parking places, the goal). ## The look: a late-summer afternoon in Trondheim · 30 September 2026
**Why.** The world was one pale lime green under flat white-blue light: lawn, meadow and forest looked the same, shadows were weak, the sky was a plain colour and the horizon empty, although Byåsen looks out over Trondheim, the fjord and the hills of Bymarka. Everything that decides how the world is lit and coloured is now in `dist/look.js` (pure functions, no WebGL needed to test them); `world.js` only calls into it, and `street-details.js` takes its road, kerb and path colours from it. The code that draws buildings and trees was left alone; buildings and trees change colour only because the light does.

**Light.** A warm sun (`#ffd9a6`) stands 37 degrees up in the west-south-west (bearing 238, afternoon light from behind the car on the main trip, which drives east), with a cool sky light from above (`#b0c9ea`) and a warm olive bounce from the ground, so lit grass is warm and shadows come out soft and blue. Output is sRGB with ACES filmic tone mapping at exposure 1.12 (1.28 before, with a sun 55 degrees up from the north-west). The shadow map is 2048 (1024) over 108 m (90 m) and follows the car 18 m ahead of it in whole texels of the light's own grid, so shadow edges no longer crawl when the car moves. The bias was found by trial (`-0.0012`, normal bias 0.08): the kerb band lies 9 cm under the asphalt and a smaller bias cast a sawtooth shadow of that step on it. Sun, sky light and pixel-ratio cap are constants at the top of `look.js` (`SUN`, `HEMI`, `RENDER`).

**Sky and horizon.** The fog (110 to 560 m, it was 165 to 510) is exactly the colour of the sky at the horizon and the dome keeps that colour from 1.5 degrees up to straight down, all the way round, so the far ground melts into the sky without a seam; the chunks are drawn to 680 m, so nothing pops. ## Roundabouts · 30 September 2026
**Why.** The eight roundabouts looked crooked (skjeive). Every ring in the OSM data is a circle to within 0.4 m and the lanes leave it where the real roads do (checked on the aerial photo), so the fault was in how the road surface was built round a circle: the ring was a ribbon level across, round a slope (a twisted strip that shaded in radial spokes, up to 90° between neighbouring triangles, the centre line up to 31 cm off a plane), a straight junction patch at every arm bulged and kinked on a circle of 7 to 16 m, the lanes ended in flat cuts, the island rim was a 12 to 17-gon, and the rings and splitter lanes had centre-line dashes. Two rings (Stabells veg, Stavset) were also 0.30 and 0.38 m out of round. Analysis, table per roundabout and numbers: `docs/roundabouts.md`.

**Now.** `map_fixes.fit_roundabouts` fits each ring as a least-squares circle and puts every ring node on it (angles kept, so the lanes, exit order and arrows stay); the street details take the same circle. `dist/road-geometry.js`: no junction patch on a ring (it is one closed ribbon, each lane ends square at its outer edge), and each ring lies in one plane. `dist/road-surface.js` (`mouth()`): each lane tilts into that plane over its last 4 m, rows of quads close the gap to the circle and a curb return (an arc tangent to the lane's edge and the ring's outer circle, at most 5 m, less beside a narrow splitter island) flares every entry and exit; the ring's kerb band and the island rim follow the plane; no dashes on rings or one-way lanes. `dist/street-details.js`: the island rim has a point every 0.8 m; a one-way entry is given way across its whole width. `dist/game.js`: the arrows' bearings are measured from the circle's least-squares centre (no label changes: all 30 entrances compared before and after). One shared-code fix on the way: a ribbon's kerb under-layer is split on the same diagonal as its asphalt and follows its tilt, so a tilted lane no longer shows its kerb through the asphalt. The top-down recipe in the toolkit README (`[x-0.01, H, z+0.01, x, 0, z]`) gives a picture turned 45°; `[x, H, z+0.01, x, 0, z]` is north up.

**Numbers.** Ring asphalt in its plane to 0.00 mm (the centre line was 6 to 31 cm off at worst), triangle normals within 0 degrees (was 8 to 14 degrees rms, 27 to 90 worst), nodes on one circle to 1 cm (was 30 and 38 cm at Stabells veg and Stavset), island centre on ring centre to 1 cm (was up to 10 cm), island diameters unchanged (within 0.05 m of the measured ones). ## Smoother driving · 2 October 2026
**Why** (the user): a lot of stutter and shadows popping in after the graphics polish. Frames themselves were cheap; the stalls came the first time a part of the world was drawn (its geometry sent to the GPU, its shaders compiled) and when a 160 m chunk switched its shadows on as its centre came within 110 m of the car.
- **Half the geometry memory.** The chunks hold nearly all of the world: 225 MB as 32-bit floats (positions, colours, normals, 75 MB each). Colours and the flat face normals now go to the GPU as 8-bit normalised integers: about 105 MB, and half the upload.
- **Everything uploaded while loading.** After the world is built, every chunk is drawn once into an 8×8 target with culling off and every chunk casting shadows, so all geometry is on the GPU and all shaders are compiled before the start button appears, not while driving.
- **No shadow pop-in.** A chunk casts shadows when its square reaches into the sun's shadow box (plus 30 m for a tall building's shadow), not when its centre is within 110 m of the car, so no shadow appears suddenly inside the box. The box is larger and further ahead (124 m, 30 m ahead of the car; it was 108 m and 18 m), so shadows begin about 90 m ahead, near where the fog starts; a shadow-map texel is 6 cm.

## RE-ward · 4 October 2026
The user: a system called "RE-ward", a kind of prestige. The RE-ward button in the settings saves what is unlocked so far and resets all progress; after starting a new game, with a few unlocks or none, it is possible to roll back to the old save and its unlocks.
- **RE-ward** (the settings, under "Begynn turen på nytt"): saves the whole progress (the trips, which give the colours and rides and the horn; the colour, the ride and what runs behind the car; the secrets KIWI, Ludvig and the duck) and starts over as a new game: no trips, the black car, no rides, nothing behind the car, no horn, the start screen. The new game unlocks from the first trip again (the colours, the cat, the rainbow trail, …). It is off while there is nothing to save.
- **Rull tilbake til lagret spill** (shown once there is a saved game, with "Lagret spill: 11 turer · KIWI · Ludvig · anda" above it): brings the latest saved game back exactly as it was, whatever the new game has become (also with nothing unlocked in it), and the new game is dropped. The unlock state is checked as every saved game is (a ride not yet earned is the car).
- **Two taps.** Both buttons change when tapped ("Trykk igjen · alt starter på nytt", "Trykk igjen · det nye spillet forkastes", yellow) and act on the second tap, within eight seconds; closing the menu or arming the other button disarms them.
- **A stack.** The saved games are a stack (the latest last, at most 20), so a RE-ward on top of a new game does not overwrite the first save: the rollback brings the latest back, the next one the one before it. The label shows how many there are ("2 lagrede").
- **Storage.** `sofiatur.re-ward` (`{v:1, saves:[…]}`, each save as in `sofiatur.fremgang`), next to the progress; a broken value is ignored and bad entries are dropped. With storage blocked the game still works and RE-ward and the rollback work while the page is open. The settings (music, camera, …) are not part of it.
- `applySaved()` and `snapshot()` in `dist/game.js` are what the game start, RE-ward and the rollback share.
Tests: `verify-rewards.mjs` (the two taps; everything reset and every unlock back; the reload; a stack of saves; damaged, capped and blocked storage). Checked in Chromium on an iPad and a phone with real clicks in the settings.
